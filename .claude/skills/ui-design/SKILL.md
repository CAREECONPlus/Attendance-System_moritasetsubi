# 勤怠管理システム UI 設計スキル

現場作業員がスマホで打刻し、管理者が PC で集計する「業務ツール（Operate モード）」のための設計規約。
目標は「驚き」ではなく「迷わない」。初見の人が説明なしで打刻でき、管理者が月次集計を数クリックで終えられること。

## 1. 進め方

1. **方向性を決めてから作る**: 新規や全面刷新のときは、主要2画面（スマホの打刻 / PC の一覧）を 2〜3 案作って見比べてもらい、1案に決めてから全画面を同じトーンで揃える。5段階のグラデーションではなく、軸の違う案を出す。
2. **モックは Design キャンバスに**: 1段目＝スマホ（390×844 固定）、2段目以降＝PC（1280 幅・`expand: fill` の可変ページ）。段の見出しは title1 ノート。ファイル名は画面名（`Main`, `History`, `C-Admin` …）。
3. **実装は画面単位の PR**: 共通部品（通知・確認・シート・パネル）→ 打刻 → 履歴 → 管理者の一覧 → 経費 → 給与 → 設定 → 従業員 の順。各 PR は Dev プレビュー（`docs/DEV_ENVIRONMENT.md`）で確認してからマージ。
4. **作ったら自分でレビュー**: 「5. 禁止事項」「6. チェックリスト」を通してから出す。

## 2. トークン

```css
:root {
  /* 色: 紺=文字と左ナビ、青=主操作・選択・現在地のみ。アクセントを飾りに使わない */
  --ink:        #001350;   /* 本文・見出し */
  --ink-muted:  #5B6386;   /* 補助文字（白地で 4.6:1） */
  --ink-faint:  #8A92B2;   /* ゼロ値・無効（大きい文字以外に使わない） */
  --primary:    #244EFF;   /* 主操作・選択状態・現在地 */
  --primary-dk: #0133D8;   /* 押下・ホバー */
  --primary-bg: #E9EEFF;   /* 選択中の背景 */
  --ground:     #F1F4FF;   /* ページ地 */
  --surface:    #FFFFFF;   /* カード・表・入力 */
  --line:       #E3E8F5;   /* カードの枠・区切り（表以外） */
  --line-strong:#C9D2F0;   /* 入力欄の枠・表の外枠・表の見出し下線（2px） */
  --line-row:   #D1D8EC;   /* 表の行の区切り線 */
  --row-alt:    #F7F9FF;   /* 表の偶数行の帯・表の見出し行の地 */
  --nav:        #001350;   /* 左ナビ地 */
  --nav-item:   #D7DDF5;   /* 左ナビの非選択文字 */
  --nav-sub:    #0A2270;   /* 左ナビのボタン地 */

  /* 状態色: 文字は濃色、地は淡色。色だけで意味を伝えず必ず文字を添える */
  --ok-fg: #0B7A4E;   --ok-bg: #DDF7EC;   --ok-dot: #1DCE85;
  --warn-fg: #7A4B00; --warn-bg: #FFF4D6; --warn-dot: #D98B00;
  --danger-fg: #B3123F; --danger-bg: #FFE4EA; --danger-line: #F3C6D2;

  /* 書体: 見出しと数字は Zen Kaku Gothic New、本文は Noto Sans JP。段階比 1.15 */
  --font-display: 'Zen Kaku Gothic New', 'Hiragino Sans', 'Yu Gothic', sans-serif;
  --font-body:    'Noto Sans JP', 'Hiragino Sans', 'Yu Gothic', sans-serif;
  --fs-11: 11px; --fs-12: 12px; --fs-13: 13px; --fs-14: 14px; --fs-15: 15px;
  --fs-16: 16px; --fs-18: 18px; --fs-20: 20px; --fs-22: 22px; --fs-28: 28px; --fs-36: 36px; --fs-44: 44px;

  /* 角丸: 役割で固定（全部同じにしない） */
  --r-chip: 6px;    /* バッジ */
  --r-ctl:  8px;    /* 表内ボタン・セレクト */
  --r-input:10px;   /* 入力欄・通常ボタン */
  --r-card: 12px;   /* カード・表の枠 */
  --r-sheet:14px;   /* ダイアログ・主ボタン（スマホ） */
  --r-pill: 999px;  /* 「この端末」などの小さなピル */

  /* 影: 浮いているものだけ。主ボタンとダイアログのみ */
  --shadow-primary: 0 8px 20px rgba(36, 78, 255, 0.25);
  --shadow-dialog:  0 20px 50px rgba(0, 19, 80, 0.25);
  --shadow-panel:  -12px 0 40px rgba(0, 19, 80, 0.18);
}
```

- 勤務種別バッジ（固定）: 通常 `#EEF1FA/#3C4670`、休日出勤 `#FFE4EA/#B3123F`、夜間のみ `#E6E8FF/#3730A3`、通し夜間 `#DCE7FF/#0133D8`、有給・代休 `#DDF7EC/#0B7A4E`、欠勤 `#F1F4FF/#5B6386`。呼び名は Excel/CSV の列名と一致させる（「夜間のみ」「通し夜間」）。
- 経費項目バッジ（設定で変更可、既定は現行アプリの色相を継承）: 駐車場代=青 `#DCE7FF/#0133D8`、工具代=緑 `#DDF7EC/#0B7A4E`、高速代=黄 `#FFF4D6/#7A4B00`、その他=灰 `#EEF1FA/#3C4670`。どの色でも文字は濃色にして 4.5:1 を守る。
- 数字は `font-variant-numeric: tabular-nums`。金額は `¥12,300`、時間は `8:00` / `12.5 時間`。

## 3. レイアウト

**スマホ（従業員）**
- 1カラム、下部に4タブ（打刻・履歴・現場・経費、高さ 74px、現在地は青）。アカウントはヘッダー右の人型アイコン。
- 主操作ボタンは画面下部に固定（ナビの上）。高さ 56〜68px、文言は動詞で終える（「出勤を記録する」「保存する」）。ボタン内の2行目に「何が登録されるか」を小さく添える。
- 選択肢は横スクロールではなく折り返すチップ（44px）。多くなる一覧は「最近使った順 N 件 ＋ その他から選ぶ」。
- 編集は下から出るシート（角丸 20px 上のみ、つまみ付き、背景を暗くする）。削除は一番下に赤文字のテキストボタン。
- 空状態は「何が無いか」「次に何をするか」「そのボタン」の3点セット。読み込み中はスケルトン。
- 一覧の行は **タップで詳細シート、左スワイプで「しまう」操作**（メールの既読/アーカイブと同じ手触り）。スワイプで出る操作は取り消せるものだけ（例: 「終わった現場に移す」）。同じ操作は詳細シートの下部にも置き、動線を2つにする。
- 言葉は現場の人の語彙で。「アーカイブ」「無効化」「非アクティブ」は使わず **「終わった現場」「また使う」「しまう」** のように、何が起きるかが分かる日本語にする。しまったものは一覧の末尾に「終わった◯◯（N件）」として残し、戻す操作を隣に置く。

**PC（管理者）**
- 左ナビ 236px（紺）、5項目（勤怠・経費精算・月次給与・従業員・設定）。ハンバーガーで 64px のアイコンレールにたためる。下にユーザー名とログアウト。
- 本文は 24〜28px の余白、`max-width` は表のある画面では無し、設定系は 960px。
- 画面の型: 見出し＋期間切替＋右に操作ボタン → 要約の帯（1本、数字カードを並べない） → 絞り込み（1行に収める） → 表（`overflow-x: auto` の箱、見出しクリックで並べ替え、合計行は `tfoot`）。
- 編集は右からのスライドパネル（460px）。背景を暗くし、下部に「削除（赤文字）｜キャンセル・保存」。
- 900px 未満ではナビが上に畳まれ、表は横スクロール、フィルターは縦積み。

## 4. 部品の規約

| 部品 | 規約 |
|---|---|
| ボタン | 主操作＝青塗り＋影、通常＝白地＋枠 `--line-strong`、取り消せない操作＝白地＋赤文字＋赤枠、無効＝灰地。押下で 0.96 倍 150ms。`transition` は変化するプロパティだけ指定（`all` 禁止） |
| 入力 | 高さ 44〜52px、枠 1.5px `--line-strong`、フォーカスは青枠＋ `0 0 0 3px rgba(36,78,255,.2)`、エラーは赤枠＋下に理由と直し方 |
| セグメント（勤務種別） | 淡い地の中に選択項目だけ白＋薄い影。`aria-pressed` を付ける |
| バッジ | 濃色文字×淡色地、角丸 6px、12px 太字 |
| 通知 | 画面上部、3秒、操作を止めない。成功＝緑、失敗＝赤（原因と対処を書く）、注意＝黄。誤操作を戻せる場合は「取り消す」を添える |
| 確認ダイアログ | 見出しに「何を・どうするか」、本文に対象と影響、ボタンは右寄せ。`prompt` の置き換えは専用フォーム |
| 表 | 外枠 `--line-strong`、見出し行は地 `--row-alt`＋下線 2px `--line-strong`、行の区切りは `--line-row`、偶数行に `--row-alt` の帯（薄い線だけだと境界が読めない）。数値は右寄せ、ゼロは `--ink-faint`、操作列は見出しを視覚的に隠す（スクリーンリーダー用に残す） |
| アイコン | 線画 SVG（stroke 2〜2.2、`currentColor`）。絵文字・Unicode 記号は使わない。アイコンだけのボタンには `aria-label` |
| 動き | 150〜250ms のみ。ページ読込の演出なし。`prefers-reduced-motion` で動きを消し不透明度だけにする |

## 5. 禁止事項（反射で選びがちな既定）

- 同じ角丸・同じ影のカードを並べて構造を作る／数字カード4枚のヒーローメトリクス
- 見出しの上の小見出し（eyebrow）、全部大文字のラベル、`01 / 02 / 03` の番号飾り
- 絵文字や「↓」「⇅」をアイコン代わりに使う
- 色だけで状態を伝える（必ず文字を併記）
- 1画面に主操作ボタンが複数ある／危険でない操作に赤を使う
- `alert` / `confirm` / `prompt`／用途の無いモーダル（まず画面内で済ませる）
- ホバーだけに依存した操作（スマホで押せない）／44px 未満のタップ領域
- 本物らしい数字・実績・ロゴの捏造。無いものは `[ロゴ画像]` のように明示した枠にする

## 6. 出す前のチェックリスト

- [ ] 文字コントラスト: 本文 4.5:1 以上、24px 以上は 3:1 以上（補助文字は `--ink-muted`、`--ink-faint` は大きな数字のゼロ値だけ）
- [ ] すべての操作が `<button>` / `<a href>` / `<input>` で、ラベル（`<label for>` か `aria-label`）がある
- [ ] キーボードで到達でき、フォーカスが見える
- [ ] 320px 幅と 200% ズームで文字が切れない・重ならない
- [ ] 空・読み込み中・エラー・無効・選択中の状態がある
- [ ] 取り消せない操作に確認があり、通知で結果が分かる
- [ ] 文言: 動詞で終わるボタン、エラーは原因＋対処、同じ操作は全画面で同じ呼び名
- [ ] 同じ部品が画面によって違う見た目になっていない

## 7. 案件固有の前提（森田設備）

- 「出勤を記録する」を押すと **8:00〜17:00・休憩60分** がその場で登録される（打刻は1日1回、退勤ボタンは無い）。時刻の修正は履歴の編集シートから。
- 勤務の種類（通常／休日出勤／夜間／通し夜間）は主ボタンの直上に置く。現場は「最近使った順」をチップで、その下に「その他の現場から選ぶ」と「現場を追加」。
- 管理者は PC 中心。月次給与は「弥生給与用CSV」「生データCSV」の2ボタンを残す（使い方を変えない）。月次の「締め」は提案段階。
- **名前のデータ**: 新規登録は `lastName` / `firstName` / `lastNameKana` / `firstNameKana` を必須で取り、`displayName` には「姓 名」を結合して従来どおり書く（一覧・勤怠レコード・CSV・弥生出力は `displayName` を読むので変更不要）。既存従業員は管理者が編集パネルで姓・名・ふりがなを設定する。分けられない名前（例: AKIHIRO）は姓だけでも保存可。未設定の従業員には一覧で「姓・名を設定」の注意バッジを出す。
- **CSV 出力はプレビューしてから保存**: 対象月・件数・列数・ファイル名・文字コードを見出しに、先頭数行を表で見せ、未入力など注意があれば黄色の帯で先に知らせる。「この内容でダウンロード」が主操作。「次回から省略」のチェックを用意する。
- パスキー対応は見送り（Firebase Auth 単体では不可。必要になれば Google ログインの追加から）。
- 管理者登録の申し込みフォームと管理者依頼の承認は今回は対象外（新規会社は BRANU が LINE で受けてテナント管理から作成）。別案件で使うときに復活させる。
- ロゴは森田設備の HP と同じ画像を使う（ファイル受領まではダッシュ枠のプレースホルダー）。
