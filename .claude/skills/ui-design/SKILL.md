# 現場向け業務ツール UI 設計スキル

現場の作業員がスマホで記録し、管理者が PC で確認・集計する「業務ツール」のための設計規約。
目標は「驚き」ではなく「迷わない」。初見の人が説明なしで記録でき、管理者が月次の集計を数クリックで終えられること。

最初に案件の前提を確認する。このリポジトリ（森田設備）の前提は `references/example-morita.md` にあるので必ず読み、そこに書かれた業務ルールと文言を優先する。別の案件では `references/project-template.md` を埋めて使う。

## 1. 進め方

1. **方向性を決めてから作る**: 新規や全面刷新では、主要 2 画面（スマホの入力画面 / PC の一覧画面）を 2〜3 案作って見比べてもらい、1 案に決めてから全画面を同じトーンでそろえる。似た案を並べず、軸の違う案を出す。
2. **全画面のモックを先にそろえる**: スマホは 390×844 固定、PC は 1280 幅。画面ごとに 1 枚。空・読み込み中・エラーの状態も描く。モックの道具は問わない（Design キャンバス、Figma、HTML 1 枚でもよい）。
3. **実装は画面単位で区切る**: 共通部品（通知・確認・シート・パネル）→ 入力画面 → 履歴 → 管理者の一覧 → 残りの画面の順。区切りごとに実機かプレビュー環境で確認してから次へ進む。Git を使う場合は区切りごとに 1 つの PR にする。
4. **作ったら自分でレビュー**: 「6. 禁止事項」「7. チェックリスト」を通してから出す。

## 2. トークン

すぐ貼れる形は `references/tokens.css`。考え方は次のとおり。

- **色**: 紺＝文字と左ナビ、青＝主操作・選択中・現在地だけ。アクセント色を飾りに使わない。ページの地は薄い青、カード・表・入力は白。
- **状態色**: 文字は濃色、地は淡色の組で持つ（成功＝緑、注意＝黄、危険＝赤）。色だけで意味を伝えず、必ず文字を添える。
- **種別の色**: 一覧のバッジと、選ぶときのボタンは同じ色にする（例: 夜間＝紫、通し夜間＝青、休日＝赤、休暇＝緑、欠勤＝灰）。種別は**色と文字で区別し、絵文字のマーク（🌙📅 など）は使わない**。
- **書体**: 見出しと大きな数字は Zen Kaku Gothic New、本文は Noto Sans JP（どちらも Google Fonts）。ボタン・入力欄・表は書体を明示しないとブラウザ既定になるので、`font-family: inherit` を必ず当てる。
- **数字**: `font-variant-numeric: tabular-nums`。金額は `¥12,300`、時刻は `8:00`、時間は `12.5 時間`。
- **角丸**: 役割で固定する（バッジ 6px、表内ボタン 8px、入力・通常ボタン 10px、カード 12px、ダイアログ・主ボタン 14px）。全部同じにしない。
- **影**: 浮いているものだけ（主ボタン、ダイアログ、シート）。カードには付けない。

## 3. レイアウト

**スマホ（作業員）**
- 1 カラム、下部に 3〜5 個のタブ（高さ 74px、現在地は青）。アカウントはヘッダー右の人型アイコン。ヘッダー左に会社のロゴ、右に日付と氏名。
- 主操作ボタンは画面下部に固定（タブの上）。高さ 56〜68px、文言は動詞で終える（「出勤を記録する」「保存する」）。ボタンの下に「何が登録されるか」を小さく添える。
- 選択肢は横スクロールではなく折り返すボタン（44px 以上）。多くなる一覧は「最近使った順 N 件＋その他から選ぶ」。めったに使わない選択肢は閉じたプルダウン（「その他の◯◯」）に入れる。
- 編集は下から出るシート（上だけ角丸 20px、つまみ付き、背景を暗くする）。削除は一番下に赤文字のテキストボタン。
- 空状態は「何が無いか」「次に何をするか」「そのボタン」の 3 点セット。今日の分が無いときは「今日はまだ記録がありません」から入力画面へ移れるようにする。
- 一覧の行は**タップで詳細シート、左スワイプで「しまう」操作**。スワイプで出す操作は取り消せるものだけ。同じ操作を詳細シートの下にも置き、動線を 2 つにする。

**PC（管理者）**
- 左ナビ 236px（紺）。三本線のボタンで 64px のアイコンだけの列にたためる。たたんだ状態は端末に記憶する。
- ナビは画面の高さに固定（`position: sticky; top: 0; height: 100vh`）し、本文をスクロールしても下のアカウントとログアウトが常に見えるようにする。
- 下位項目を持つグループ（例: 勤怠＞日別・月別…）は、たたんだときは下位項目を隠してグループのアイコンだけにする。そのアイコンを押すとナビが開いて下位項目が見える。開いているときに押したら最初の下位項目を表示する。押しても何も起きないアイコンを作らない。
- 画面の型: 見出し＋期間切替＋右に操作ボタン → 要約の帯（1 本） → 絞り込み（1 行に収める） → 表（横スクロールの箱、見出しクリックで並べ替え、合計行は `tfoot`）。
- 編集は右からのパネルか中央のダイアログ。下部に「削除（赤文字）｜キャンセル・保存」。
- 900px 未満ではナビを上に畳み、表は横スクロール、絞り込みは縦に積む。

## 4. 部品の規約

| 部品 | 規約 |
|---|---|
| ボタン | 主操作＝青塗り＋影、通常＝白地＋枠、取り消せない操作＝白地＋赤文字＋赤枠、無効＝灰地。押下で 0.96 倍 150ms。`transition` は変化するプロパティだけ（`all` 禁止）。グラデーション塗りは使わない |
| 入力 | 高さ 44〜52px、枠 1.5px、フォーカスは青枠＋薄い青の外光、エラーは赤枠＋下に理由と直し方 |
| 種別の選択 | 白地＋薄い枠のボタンを並べ、選択中はそのバッジ色で塗り、文字色の枠とチェックマークを付ける。`aria-pressed` を付ける |
| バッジ・状態 | 濃色文字×淡色地、角丸 6px、12px 太字。有効・無効のような状態は「● 有効」のように丸い点＋文字でもよい |
| 通知 | 画面上部、3 秒、操作を止めない。成功＝緑、失敗＝赤（原因と対処を書く）、注意＝黄。戻せる操作には「取り消す」を添える |
| 確認 | 見出しに「何を・どうするか」、本文に対象と影響、ボタンは右寄せ。ブラウザ標準の `alert` / `confirm` / `prompt` は使わない |
| 表 | 外枠は濃いめの線、見出し行は薄い地＋下線 2px、行の区切り線、偶数行に薄い帯（薄い線だけだと境界が読めない）。数値は右寄せ、ゼロは薄い色 |
| CSV 出力 | 保存する前に中身を確認させる。表計算ソフトのように列 A・B・C と行番号、全セルの罫線で先頭数十行を見せ、行数・列数・ファイル名・文字コードを見出しに書く。注意事項は黄色の帯で先に知らせる。「この内容でダウンロード」が主操作。「次回から確認を省略」を用意する |
| 外部サービス連携 | Google などの連携はログイン時に要求しない。連携が必要な操作を押したときに「◯◯する場合は連携が必要です」と案内して設定を開く。設定画面の表示も「未連携（エラー）」ではなく案内文＋「連携する」ボタンにする |
| アイコン | 線画 SVG（stroke 2〜2.2、`currentColor`）。絵文字・Unicode 記号は使わない。アイコンだけのボタンには `aria-label` と `title` |
| 動き | 150〜250ms のみ。`prefers-reduced-motion` で動きを消す |

## 5. 文言

- **既存アプリを刷新するときは、ボタン・項目・種別の名前を変えない**（例: 「出勤」「夜間のみ」「通し夜間」「保存」「削除」）。見た目が変わるだけで使い方は同じ、と伝わることを優先する。名前を変えるのは、実態と合っていない名前を直すときだけにし、変えたものは一覧にして利用者へ知らせる。
- 新しく作る言葉は、現場の人の語彙にする。「アーカイブ」「無効化」「非アクティブ」ではなく「終わった現場」「また使う」「しまう」のように、何が起きるか分かる日本語にする。
- ボタンは動詞で終える。エラーは「原因＋対処」。同じ操作は全画面で同じ呼び名。
- 業務の呼び名は Excel や CSV の列名と一致させる。

## 6. 禁止事項（反射で選びがちな既定）

- 同じ角丸・同じ影のカードを並べて構造を作る／数字カード 4 枚の飾りの指標
- 見出しの上の小見出し、全部大文字のラベル、`01 / 02 / 03` の番号飾り
- 絵文字や「↓」「⇅」をアイコン代わりに使う、種別を絵文字のマークで示す
- グラデーションのボタンやバッジ、色付きの太い左線だけで区別するカード
- 色だけで状態を伝える
- 1 画面に主操作ボタンが複数ある／危険でない操作に赤を使う
- `alert` / `confirm` / `prompt`／用途の無いモーダル
- ホバーだけに依存した操作／44px 未満のタップ領域
- 押しても何も起きないアイコンやラベル
- 本物らしい数字・実績・ロゴの捏造。無いものは `[ロゴ画像]` のように明示した枠にする。説明用の画面画像は「山田 太郎」「サンプル現場A」のような明らかなサンプルデータで作る

## 7. 出す前のチェックリスト

- [ ] 文字コントラスト: 本文 4.5:1 以上、24px 以上は 3:1 以上
- [ ] すべての操作が `<button>` / `<a href>` / `<input>` で、ラベルがある
- [ ] キーボードで到達でき、フォーカスが見える
- [ ] 320px 幅と 200% ズームで文字が切れない・重ならない
- [ ] 空・読み込み中・エラー・無効・選択中の状態がある
- [ ] 取り消せない操作に確認があり、通知で結果が分かる
- [ ] 書体がボタン・入力欄・表・通知まで統一されている
- [ ] 文言が既存と同じ（刷新の場合）、または現場の語彙になっている
- [ ] 同じ部品が画面によって違う見た目になっていない
- [ ] 既存アプリの刷新では `references/retrofit.md` のチェックも通した（タブ画面は「別のタブを経由して開く」でも確認した）
