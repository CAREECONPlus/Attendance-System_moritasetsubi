# 案件の前提（例: 勤怠管理システム／森田設備）

## 基本
- 利用会社: 森田設備（設備工事）。実質この 1 社専用で、他は開発会社の確認用テナントのみ
- 利用者: 作業員はスマホ、管理者は PC
- 技術: 素の HTML / JS、Firebase（Auth / Firestore）、本番は GitHub Pages。確認環境は Firebase Hosting の Dev プロジェクト（固定 URL）
- 進め方: 画面単位の PR → Dev の固定 URL で確認 → main にマージで本番へ（手順は `docs/DEV_ENVIRONMENT.md`）
- 管理者のナビ: 勤怠（日別・月別・従業員別・現場別）・経費精算・月次給与・従業員招待・従業員管理・設定
- モック: Design キャンバス「勤怠管理システム UI刷新モック」（2026-10 作成）
- ロゴ: 森田設備の HP と同じ画像

## 業務ルール
- 「出勤を記録する」を押すと 8:00〜17:00・休憩 60 分がその場で登録される（1 日 1 回、退勤ボタンは無い）。時刻の修正は履歴の編集から
- 種別: 出勤／休日出勤／夜間のみ／通し夜間／有給／代休／欠勤。打刻画面は 4 種類のボタン＋「その他の勤務（有給休暇・代休・欠勤）」の閉じたプルダウン
- 費目: 駐車場代＝青、工具代＝緑、高速代＝黄、その他＝灰
- 集計: 月次給与は「弥生給与用 CSV」「生データ CSV」の 2 つを残す。勤怠一覧の明細 CSV は「明細 CSV 出力」（旧「特殊勤務 CSV 出力」）
- 経費は「その日・その現場」単位でも見られる（日付×現場の小計、絞り込み、合計、CSV）

## 文言
- 呼び名は刷新前と同じ（出勤・休日出勤・夜間のみ・通し夜間・有給・代休・欠勤、勤怠記録の編集、経費を追加、保存、削除）
- 夜間は月のマークではなく色（紫）で区別する
- 現場の終了は「終わった現場」「また使う」

## データ
- 新規登録は lastName / firstName / lastNameKana / firstNameKana を取り、displayName には「姓 名」を書く（一覧・CSV は displayName を読む）
- 既存の利用者の名前は分け直さない
- 権限は users（テナント配下）と global_users の両方の role を見る

## 対象外・保留
- パスキー（Firebase Auth 単体では不可。必要になれば Google ログインの追加から）
- 管理者登録の申し込みフォームと管理者依頼の承認（新しい会社は開発会社が LINE で受け、テナント管理から作成する）
